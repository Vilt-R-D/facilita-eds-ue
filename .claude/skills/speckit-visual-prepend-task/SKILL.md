# Visual Reference Phase Injector

Dispatched by `/speckit-tasks` step 6 (after_tasks mandatory hook) when the `visual-refs` extension is registered in `.specify/extensions.yml`. Reads the active feature's `spec.md` `**Input**:` line, extracts every PNG/SVG reference (path or http(s) URL), and injects (or refreshes) a `## Phase 0: Visual Context` block immediately before `## Phase 1:` in `tasks.md`. The block carries one task per reference so `/speckit-implement` loads each image into context before any code task.

Idempotent: re-running with unchanged input yields byte-identical `tasks.md`. Any failure leaves `tasks.md` untouched and surfaces a single-line warning — never aborts the parent `/speckit-tasks`.

Use the Read/Edit/Write tools directly. The hook is fully LLM-driven — there are no shell scripts to delegate to.

## Behavior

1. **Resolve the active feature directory**:
   - Read `.specify/feature.json`. If the JSON parses and has a non-empty `feature_directory`, treat that (relative to repo root) as the feature dir.
   - If `feature.json` is missing or unparseable, fall back to scanning the current git branch name with `.specify/scripts/bash/common.sh::find_feature_dir_by_prefix` (or its PowerShell equivalent). If no match, fail per the failure mode below.

2. **Locate the `**Input**` line in `<featuredir>/spec.md`**:
   - Match the literal regex `^\*\*Input\*\*: User description: "(?<payload>.+)"\s*$` (multiline). If absent or quoting unbalanced (no closing `"`), trigger failure mode.

3. **Extract image references from the quoted payload** (preserving order, deduped):
   - **Pair pattern** (precedence): a token ending `.png|.svg` followed by `:` then a `https?://` URL ending `.png|.svg` (with optional `?<query>`). Capture the LABEL verbatim and the URL verbatim. Strip wrap chars (`"' < ( ` from start, `"' > ) . , ; :` from end) on each.
   - **Orphan tokens**: any whitespace-bounded token ending `.png|.svg` (with optional `?<query>`) NOT consumed by a pair. Strip the same wrap chars. Derive label as the basename — strip everything up to and including the last `/` or `\`, then strip `?<query>` if present. If basename ends up empty, fall back to the raw token.
   - Dedupe by full string (label+url for pairs, raw token for orphans), preserving first-seen order. Emit pairs first, then orphans.

4. **Read `<featuredir>/tasks.md`**.

5. **Strip any pre-existing Phase 0 block** before computing the new content:
   - Detection anchor: literal line `## Phase 0: Visual Context (Pre-Implementation)`.
   - Strip range: from the first line equal to that anchor, through the immediately following lines, up to (but NOT including) the next line whose literal prefix is `## Phase 1:`. Any blank lines or `---` separators sitting between the Phase 0 block and `## Phase 1:` are part of the strip range — leave only `## Phase 1:` and what follows.
   - Match the anchor and the `## Phase 1:` line by literal string equality / prefix on their own line (no regex needed).
   - Also strip any legacy block delimited by `<!-- visual-context-task:start -->` / `<!-- visual-context-task:end -->` (early-format leftover from the bash hook era), plus one trailing blank line if present.
   - Before stripping, count the visual-task IDs the prior Phase 0 used (lines matching `^- \[ \] T0\d\d ` inside the strip range). Call that count `K_old` — step 8 needs it to undo the prior shift before applying the new one.

6. **Skip-write rule**: if no refs were extracted in step 3, write the cleaned file (Phase 0 stripped) AND undo any prior shift (step 8) so feature tasks reclaim `T001..Tn`. Exit silently. Result MUST be byte-identical to a `tasks.md` that never had a Phase 0 block.

7. **Locate the insertion point**: the line index of the first heading matching `^## Phase 1:` (literal prefix). If absent, trigger failure mode (`tasks.md` not generated by /speckit-tasks).

8. **Renumber feature tasks to free `T001..TK`** where `K` = number of refs extracted in step 3:
   - First, undo the prior shift if a CURRENT block existed (step 5 captured `K_old`): subtract `K_old` from every `T0\d\d` ID in the file (and every cross-reference to those IDs in Dependencies, Parallel Examples, Implementation Strategy, Notes, etc.).
   - Then, apply the new shift: add `K` to every remaining `T0\d\d` ID and every cross-reference to those IDs throughout the file. Process IDs in DESCENDING numeric order (or use a placeholder two-pass: first pass replaces every `T0XY` with `__TID_T0XY__`, second pass replaces each placeholder with the shifted ID) to avoid collisions during in-place rewrite.
   - Be careful: `T0\d\d` is the only task-ID shape produced by /speckit-tasks; do NOT touch incidental digit sequences elsewhere (URLs, AWS dates like `T185126Z`, etc.). Anchor the regex to require exactly three digits and start with `T0`.

9. **Build the new block** — exact format, no variations, no HTML-comment delimiters:

   ```markdown
   ## Phase 0: Visual Context (Pre-Implementation)

   **Purpose**: Load each design reference into model context before any implementation task. Phase 1 begins after every reference has been loaded.

   - [ ] T001 Load `<label-1>` into context
     - Source: <url-1>
   - [ ] T002 Load `<label-2>` into context
     - Source: <url-2>
   ... (one entry per ref, sequential T001 / T002 / T003 ... in extraction order)

   ---
   ```

   - Task IDs use the same `T<NNN>` 3-digit format as the rest of `tasks.md`. Visual tasks claim the FIRST `K` IDs (`T001..TK`); feature tasks were shifted up by `K` in step 8 so they now occupy `T(K+1)..T(K+M)`.
   - For pair refs: `<label-N>` is the captured label (verbatim, with extension); `<url-N>` is the captured URL.
   - For orphan refs: `<label-N>` is the derived basename; `<url-N>` is the raw token.
   - The `---` separator at the bottom of the block keeps Phase 0 visually delimited from Phase 1 in the rendered Markdown.
   - Visual tasks have NO `[P]` marker and NO `[Story]` label — Phase 0 is its own scope, runs sequentially before Phase 1.

10. **Insert the block** immediately before the `## Phase 1:` heading, with exactly one blank line between the trailing `---` and `## Phase 1:`.

11. **Idempotency**: re-running this skill with unchanged `spec.md` MUST yield a byte-identical `tasks.md` (Phase 0 + tasks regenerated in place; shift accounting matches). The undo-then-apply pattern in step 8 makes shift idempotent across runs.

12. **Atomic write**: build the new file content fully in memory before issuing a single Edit/Write. Never partially mutate.

## Failure mode

On any failure (missing feature dir, malformed `**Input**`, missing `## Phase 1:` heading, unwritable file, etc.):

1. Leave `tasks.md` byte-identical.
2. Emit one warning line to the user:

   ```text
   [specify] Warning: visual-refs after_tasks failed: <reason>; tasks.md preserved
   ```

3. Allow the parent `/speckit-tasks` to continue reporting SUCCESS for its own write.

## Output contract example

Given a feature whose `spec.md` `**Input**` payload contains:

```text
... themes. Module_CardsStackDesktop.svg: https://cdn.example.com/abc.svg?sig=1 Module_CardsStackMobile.svg: https://cdn.example.com/def.svg?sig=2
```

The block injected before `## Phase 1:` is:

```markdown
## Phase 0: Visual Context (Pre-Implementation)

**Purpose**: Load each design reference into model context before any implementation task. Phase 1 begins after every reference has been loaded.

- [ ] T001 Load `Module_CardsStackDesktop.svg` into context
  - Source: https://cdn.example.com/abc.svg?sig=1
- [ ] T002 Load `Module_CardsStackMobile.svg` into context
  - Source: https://cdn.example.com/def.svg?sig=2

---
```
