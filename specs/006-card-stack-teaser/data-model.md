# Data Model — Card Stack Teaser

Authoring-side content model. The block holds no runtime persistence — all "state" is the in-memory `currentIndex` plus DOM attributes set by `decorate()`. The Universal Editor schema in `_card-stack-teaser.json` is the source of truth for authored fields; this document mirrors it for review and links each field to a spec requirement.

## Entities

### 1. Card Stack Teaser (block)

| Field | UE component | Value type | Required | Spec ref | Notes |
|---|---|---|---|---|---|
| `title` | `richtext` | string | yes | FR-002, FR-019 | Inline markup allowed: `<strong>`, `<em>`, `<br>`, link inline. Rendered above `text` in desktop, top of vertical stack in mobile. |
| `text` | `richtext` | string | yes | FR-002, FR-019 | Same richtext rules as `title`. |
| `cta` | `aem-content` | string (path) | no | FR-015 | When absent, the CTA wrapper is suppressed (Acceptance Scenario 1.2). |
| `ctaText` | `text` | string | no | FR-015 | Required iff `cta` is set; otherwise ignored. |

**Items** (repeating, see entity 2): a list of `card-stack-teaser-card` items grouped via the block's filter.

### 2. Card (item type `card-stack-teaser-card`)

One per authored card. Items group via field-name prefix in the rendered HTML (Constitution Principle I) — each card lands in its own `<div>` row inside the block.

| Field | UE component | Value type | Required | Spec ref | Notes |
|---|---|---|---|---|---|
| `cardIcon` | `reference` | string (asset path) | no | FR-009 | Image or SVG uploaded by the author. When absent, card renders text-only without breaking layout (Edge case: "Card sem ícone autorado"). |
| `cardLabel` | `richtext` | string | yes | FR-009, FR-019 | Richtext — inline markup permitted (`<strong>`, `<em>`, `<br>`, link inline). Renamed from `cardText` to satisfy `xwalk/no-orphan-collapsible-fields` lint rule (the `Text` suffix would orphan without a base `card` field). |
| `cardTheme` | `select` | string | no | FR-013, Clarification Q2 | Closed list: `black`, `dark-green`, `light-green`, `white`. Default fallback `white` applied JS-side when missing or unknown. |

### 3. Dot (rendered, not authored)

Generated by `decorate()`. Exists only when there are 2+ cards (FR-005, FR-011).

| Property | Type | Source | Notes |
|---|---|---|---|
| element | `<button type="button">` | JS | Tabbable; FR-020. |
| `aria-label` | string | JS | "Avançar para o próximo card". |
| `aria-current` | `"true"` / absent | JS | Set on the dot whose index equals `currentIndex`. |

### 4. CTA (rendered)

Generated by `decorate()` only when `cta` AND `ctaText` are both set.

| Property | Type | Source | Notes |
|---|---|---|---|
| element | `<a class="card-stack-teaser-cta" href="${cta}">${ctaText}</a>` | JS | Inherits hover/focus styles from the project's button tokens. FR-015. |

### 5. Theme (rendering tokens)

Per-card scoped CSS custom properties declared inside `.card-stack-teaser .card-stack-teaser-card[data-theme="…"]`:

| Theme value | Background | Foreground (text) | Icon tint |
|---|---|---|---|
| `black` | dark / black token | light / white | light |
| `dark-green` | dark green token | light | light |
| `light-green` | light green token | dark | dark |
| `white` (default) | white | dark / text-color token | dark |

Concrete colour values come from the attachment files (`css-desktop.txt` / `css-mobile.txt`) at implementation time per Constitution Principle VII. This document only fixes the slot names and the four-value enumeration.

## State

The block keeps a single integer `currentIndex` in a closure scope inside `decorate()`. There is no module-level state — every block instance is independent.

| State key | Type | Initial | Transitions |
|---|---|---|---|
| `currentIndex` | integer | `0` | `currentIndex = (currentIndex + 1) mod cardCount` on each completed advance. |
| `pendingAdvance` | boolean | `false` | `true` when a click arrives during an in-flight transition; consumed (set back to `false`) on `transitionend`, which then triggers exactly one more advance. FR-017. |

## Validation rules (authoring-side)

- `title`, `text`, `cardText` cannot be empty (UE `required: true`).
- `cardTheme` is constrained to the four listed values (UE select). When the authored value is missing or unrecognised, the JS fallback substitutes `white` (Clarification Q2 / Edge case "Tema de card inválido/ausente").
- `ctaText` is meaningless without `cta` and vice-versa: render the CTA only when both are non-empty.

## Validation rules (runtime)

- `cardCount === 0` → suppress the right column entirely; only the left column (title/text/CTA) renders. (Edge case: "0 cards autorados".)
- `cardCount === 1` → render the single card, no dots, no click-to-advance binding. (FR-011 + Acceptance Scenario 2.4.)
- `cardCount >= 2` → render dots + bind click on the visible card and on each dot.

## Relationships

```text
Card Stack Teaser (1) ───< Card (0..N)
                          └── data-theme ∈ Theme palette
```

Cards have no parent reference back to the block in authored content; the relationship is positional inside the block's items list.
